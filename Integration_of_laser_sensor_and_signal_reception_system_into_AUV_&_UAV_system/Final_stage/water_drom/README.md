# Распознавание цифр на кубиках с подводного дрона

Читает чёрные цифры с жёлтых граней кубиков в видеопотоке в реальном времени.
Работает **локально и без интернета**: модель обучается на этой же машине из
системных шрифтов, никакие веса и датасеты скачивать не нужно.

## Быстрый старт

```bash
pip install -r requirements.txt   # numpy, opencv-python, pillow — один раз
python train_model.py             # ~15 минут, создаёт model/digit_mlp.xml
python run_realtime.py            # разбор vid4.avi с окном просмотра
```

Дальше сеть не нужна вообще.

## Работа с источником видео

```bash
python run_realtime.py --source 0            # камера или карта захвата
python run_realtime.py --source rtsp://…     # поток с дрона
python run_realtime.py --no-display          # без окна, только консоль (борт)
python run_realtime.py --save out.mp4        # записать видео с разметкой
python run_realtime.py --loop                # крутить файл по кругу
```

Клавиши в окне: `q` — выход, `пробел` — пауза, `d` — показать маски детектора.

В консоль строка печатается в момент, когда набор уверенно распознанных цифр
меняется:

```
[  4.15s] 8(0.71) 6(0.63)
[  5.80s] 8(0.74) 6(0.66) 3(0.51)
```

## Скорость

Замеры на этой машине, видео 320×240, только CPU:

| Этап | мс/кадр |
|---|---|
| детектор (жёлтый + black-hat + компоненты) | 1.9 |
| весь конвейер с классификацией и трекингом | 5.5 |

Это **~180 кадров/с** при исходных 20 кадрах/с у дрона — запас почти
десятикратный, так что реальное время держится с большим зазором даже на
слабом бортовом компьютере.

## Точность — что измерено

Числа честные, вместе со слабыми местами.

**Модель на отложенной синтетике:** 0.937 по 11 классам; класс «не цифра» —
0.980. Это верхняя оценка, реальные кадры сложнее.

**Покадрово, на 7 кадрах `vid4.avi` с эталоном, размеченным глазами**
(29 цифр, ключи `--conf 0.7 --per-cube 2`):

| | значение |
|---|---|
| precision | 0.57 |
| recall | 0.45 |
| F1 | 0.50 |

**После голосования по треку** (5 участков видео, 21 цифра) — то, что
реально выводится в консоль:

| порог `--score` | precision | recall |
|---|---|---|
| 0.8 (по умолчанию) | 0.88 | 0.33 |
| 0.7 | 0.67 | 0.38 |

Смысл настройки по умолчанию: **почти всё, что названо, названо верно**, но
примерно две трети кубиков остаются неназванными. Для задачи «дрон нашёл
кубик и прочитал номер» ложный номер обычно хуже пропуска, поэтому порог
выбран в сторону точности. Нужно больше находок — снизьте `--score` до 0.6-0.7
и `--hits`.

Эталон маленький (29 и 21 цифра), поэтому числа стоит читать как порядок
величины, а не как точную оценку. Воспроизвести: `python tools/evaluate.py`.

**Где теряется точность.** Не в детекторе — цифры находятся на кадре
уверенно. Теряется на классификации в трудных условиях: сильный смаз при
движении дрона, затенённая грань куба, цифра на дальнем кубике высотой
8-10 пикселей. Самый действенный способ поправить — разметить свои кадры
(см. ниже), а не подкручивать пороги.

## Как это устроено

Четыре шага, все на CPU.

**1. Где искать — жёлтые грани.** HSV-маска жёлтого, морфологическое закрытие,
заливка контуров. Получается область граней вместе с цифрами внутри.
Цвет отсекает фон бассейна сразу и надёжно.

**2. Что искать — тёмные штрихи.** Внутри жёлтой области считается
`black-hat` по яркости: операция вытаскивает мелкие тёмные детали на светлом
фоне и попутно убирает градиент освещения. Это важно: у куба верхняя грань
залита светом, а боковая в тени, и любой глобальный порог одну из них теряет.
Порог по Оцу берётся только по пикселям внутри жёлтого.

**3. Что из этого цифра — фильтр по геометрии.** Связные компоненты отсеиваются
по площади, соотношению сторон, заполненности bbox, доле пикселей вдали от края
грани и вытянутости минимального прямоугольника — последнее убирает рёбра куба,
которые тоже тёмные. Каждая выжившая компонента приводится к бинарному
патчу 28×28 с сохранением пропорций.

**4. Что за цифра — классификатор.** Признаки HOG + огрублённые пиксели,
модель — перцептрон `cv2.ml.ANN_MLP` на 11 классов: цифры 0–9 и отдельный
класс «не цифра» для мусора, который прошёл геометрию.

**Плюс время.** Отдельный кадр 320×240 из мутной воды ненадёжен: смаз, блик,
тень. Но кубик виден десятки кадров подряд. Трекер по центрам сопровождает
цифру между кадрами и копит взвешенные уверенностью голоса; ответом становится
победитель голосования. Цифра объявляется устойчивой после 8 попаданий при доле
голосов ≥ 0.8. Это главный источник надёжности: ошибка отдельного кадра
растворяется в голосовании.

Важная деталь: голосует и класс «не цифра». Мусорный трек набирает голоса
против себя и не проходит порог, поэтому отсеивать мусор **до** трекера
вредно — именно эти голоса его и топят. Ключ `--per-cube` (ограничение числа
цифр на кубике) полезен для покадрового режима, но по умолчанию выключен.

Ещё одна особенность данных: цифры напечатаны на разных гранях, поэтому в
кадре лежат под произвольным углом, кратным 90°. Классификатор перебирает
четыре поворота патча и берёт лучший — без этого теряется примерно половина
цифр. Оборотная сторона: 6 и 9 — это один и тот же контур, повёрнутый на 180°,
и различить их по картинке нельзя. Небольшая премия за меньший поворот делает
поведение предсказуемым: цифра, стоящая в кадре прямо, читается как есть.
(На кубиках под каждой цифрой напечатана метка-подчёркивание, задающая «низ»;
на 320×240 она слишком мелкая, чтобы на неё опираться, но на записи получше
это надёжный способ развести 6 и 9.)

## Откуда берутся обучающие данные

`cube_digits/synth.py` рендерит цифры 15 системными шрифтами Windows и
прогоняет через ту же деградацию, что видна на записи: наклон грани
(перспектива), поворот ±38°, изменение толщины штриха, масштаб до реальных
8–42 px высоты, низкий контраст, гауссово размытие, смаз движения, шум,
случайные разрывы штриха. Затем бинаризация и та же нормализация, что в
детекторе, — обучение и работа видят патчи одного вида.

Отрицательный класс генерируется отдельно: отрезки (рёбра куба), эллипсы
(блики и точки на гранях), случайные многоугольники и дуги.

## Дообучение на своём видео

Синтетика покрывает форму цифр, но не знает вашей воды, шрифта на кубиках и
характерного мусора (рёбра, блики, тени). Именно на мусоре модель ошибается
чаще всего, и лечится это несколькими сотнями размеченных вручную вырезов:

```bash
python tools/harvest.py vid4.avi --out data/raw     # нарезать кандидатов
python tools/label.py --raw data/raw --out data/labeled   # разметить: 0-9, x=мусор
python train_model.py --real-dir data/labeled       # переобучить с ними
```

В `data/labeled/` уже лежит стартовая разметка — 198 вырезов из `vid4.avi`
(72 цифры и 126 примеров мусора). Разметка одного выреза — одно нажатие
клавиши, полчаса работы заметно поднимают точность.

Проверить, что стало лучше:

```bash
python tools/evaluate.py vid4.avi --gt data/ground_truth.json
```

`data/ground_truth.json` — это `{номер кадра: [цифры, видимые глазом]}`;
дописывайте туда свои кадры.

## Настройка под другую воду и другие кубики

Все пороги детектора собраны в одном месте — `cube_digits/detector.Params`.
Что меняют чаще всего:

| Параметр | Смысл |
|---|---|
| `hsv_lo` / `hsv_hi` | диапазон жёлтого; при другой воде сдвигается оттенок |
| `min_face_area` | минимальный размер грани в пикселях — отсекает дальние кубики |
| `blackhat_ksize` | чуть больше толщины штриха цифры |
| `min_area`, `min_h` | нижняя граница размера цифры |
| `max_elong` | отсев рёбер куба; меньше — строже |

Порог уверенности голоса задаётся ключом `--conf` (по умолчанию 0.30).

Подобрать HSV удобно по маскам: запустить с окном и нажать `d`.

## Структура

```
cube_digits/
    detector.py     поиск цифр на кадре (жёлтый -> black-hat -> геометрия)
    classifier.py   HOG + MLP, перебор поворотов, предсказание
    tracker.py      сопровождение между кадрами и голосование по времени
    synth.py        генератор обучающей выборки из системных шрифтов
tools/
    harvest.py      нарезка кандидатов из видео для разметки
    label.py        ручная разметка вырезов (0-9 / мусор)
    evaluate.py     измерение точности по эталонным кадрам
data/
    labeled/        стартовая разметка: 198 вырезов из vid4.avi
    ground_truth.json  эталонные кадры для tools/evaluate.py
train_model.py      обучение, сохраняет model/digit_mlp.xml
run_realtime.py     основной скрипт реального времени
```
