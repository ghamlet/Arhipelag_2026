## [Класс Yolo](https://docs.geoscan.ru/pioneer/programming/python/pio-rknn.html#id10)

Класс **Yolo** инкапсулирует логику работы с моделью YOLO: загружает модель, выполняет инференс по входному изображению и проводит постобработку для получения координат объектов, классов и уверенности детекции.

Подсказка

Поддерживаемые архитектуры:

- yolov8
- yolov11



Чтобы перевести модель YOLO из формата `.pt` (PyTorch) в формат `.rknn` (для процессоров Rockchip NPU, например, RK3588, RK3568), вам нужно пройти через промежуточный формат **ONNX**.

Напрямую конвертировать `.pt` в `.rknn` нельзя — это ограничение официального инструментария Rockchip Toolkit.

------

## Шаг 1: Экспорт из `.pt` в `.onnx`

Экспорт выполняется стандартными средствами Ultralytics. Важно использовать правильные параметры, чтобы архитектура модели корректно легла на NPU.

Запустите этот скрипт на вашем компьютере:

```python
from ultralytics import YOLO

# Загружаем вашу модель (детекция или сегментация)
model = YOLO("yolo11n-seg.pt") 

# Экспортируем в ONNX с фиксацией размера картинки
model.export(format="onnx", imgsz=640, opset=12)
```

*На выходе вы получите файл `yolo11n-seg.onnx`.*

------

## Шаг 2: Установка RKNN-Toolkit2

Конвертация в `.rknn` происходит с помощью утилиты **rknn-toolkit2**.

1. Скачайте официальный репозиторий: [rockchip-linux/rknn-toolkit2](https://github.com/rockchip-linux/rknn-toolkit2).
2. Установите пакет на компьютер с архитектурой **Ubuntu x86_64** (Rockchip рекомендует выполнять конвертацию на хост-компьютере, а не на самой плате вроде Orange Pi).

------

## Шаг 3: Конвертация ONNX в RKNN (Python-скрипт)

Создайте файл `convert.py` рядом с вашим `.onnx` файлом. Ниже представлен базовый скрипт конвертации:

```python
from rknn.api import RKNN

# Инициализируем объект RKNN
rknn = RKNN(verbose=True)

# 1. Конфигурируем модель под чип (например, rk3588, rk3568, rk3566)
# mean_values и std_values зависят от препроцессинга Ultralytics (деление на 255)
rknn.config(
    mean_values=[[0, 0, 0]], 
    std_values=[[255, 255, 255]], 
    target_platform='rk3588'
)

# 2. Загружаем ONNX модель
print('--> Loading ONNX model')
ret = rknn.load_onnx(model='yolo11n-seg.onnx')
if ret != 0:
    print('Load model failed!')
    exit(ret)

# 3. Строим модель (здесь можно включить квантование do_quantization=True)
print('--> Building model')
ret = rknn.build(do_quantization=False)
if ret != 0:
    print('Build model failed!')
    exit(ret)

# 4. Экспортируем готовый файл .rknn
print('--> Export RKNN model')
ret = rknn.export_rknn('yolo11n-seg.rknn')
if ret != 0:
    print('Export rknn failed!')
    exit(ret)

print('Done!')
rknn.release()
```

------

## ⚠️ Важные нюансы для YOLO и RKNN

1. **Квантование (INT8)**: Если вы хотите, чтобы модель работала на NPU максимально быстро, ее нужно квантовать (`do_quantization=True`). Для этого в метод `rknn.build()` нужно будет передать текстовый файл со списком путей к 20–50 реальным картинкам из вашего датасета для калибровки.

2. Кастомные слои (Outputs)

   : Самая частая проблема при конвертации YOLO в RKNN — сложная структура выходных слоев (Detect/Segment head). NPU Rockchip не всегда может эффективно переварить операции вроде 

   ```
   Split
   ```

    или 

   ```
   Concat
   ```

    на выходе.

   - *Решение*: В официальном репозитории `rknn-toolkit2` в папке `examples/onnx/yolov8` или `yolov11` лежит готовый доработанный скрипт конвертации, который автоматически «отрезает» тяжелый выходной слой (Post-processing) от модели, перенося его выполнение на CPU, а тяжелую математику оставляет на NPU.

Поскольку ваши классы (`green` и `orange`) завязаны на цвет, а главная сложность — это сетка и блики, вот 3 оптимальных варианта для генерации и тестов:

------

## Версия 1: «Геометрический шторм» (Базовая и самая надежная)

*Цель: Научить модель идеально видеть лодки под любым углом и любого размера, не ломая цвета.*

- **Flip:** Horizontal & Vertical (Отражения во все стороны).
- **90° Rotate:** Включить (Повороты по часовой и против).
- **Rotation:** В пределах от **-45° до +45°** (Лодки смогут плыть по любым диагоналям).
- **Crop:** От **0% до 15%** (Симуляция того, что лодка частично уплыла за край кадра).
- *Остальное: Выключено.*

## Версия 2: «Борьба с бликами и тенями» (С упором на свет)

*Цель: Защитить модель от изменения освещения в помещении, ярких бликов ламп на воде и теней от бортов бассейна.*

- **Flip** и **90° Rotate:** Включить (Базовая геометрия нужна всегда).
- **Brightness (Яркость):** Между **-25% и +25%** (Моделирует глубокие тени и пересветы).
- **Exposure (Экспозиция):** В пределах **-15% и +15%** (Симулирует программное осветление/затемнение камеры).
- **Saturation (Насыщенность):** Между **-15% и +15%** (Поможет, если вода станет более блеклой или наоборот зеленоватой).
- *Остальное: Выключено. Цветовой тон (Hue) не трогаем, чтобы не превратить оранжевый в зеленый.*

## Версия 3: «Плохая камера» (С упором на текстуру и шум)

*Цель: Помочь модели распознавать маркеры через ячейки черной сетки и при плохом качестве/фокусировке видеопотока.*

- **Flip** и **90° Rotate:** Включить.
- **Rotation:** От **-20° до +20°**.
- **Noise (Шум):** Добавить **до 5%** от площади (Симулирует рябь матрицы камеры в темноте).
- **Brightness:** Между **-15% и +15%**.
- *Остальное: Выключено.*
